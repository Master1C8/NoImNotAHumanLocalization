# Launcher verification boundaries and regression recipes

The native engine tests reconstruct real files from real game originals and the delivered payload. `NOHUMAN_TESTING` injects interruption after actual promotions; shipping binaries omit these hooks. Tests cover wrong game build/code, foreign proxy ownership, rollback between writes, journal recovery in a fresh process, the first 410-file postcondition, unchanged repetition, unrelated mod preservation and pinned inventory/chunk corruption. They do not replace or establish game/UI behavior.

A compression-only cache upgrade is a separate test. Use `test_engine.py --upgrade-game <verified-previous-test-game>`, with unchanged target hashes and an existing legacy flat cache. Verify both the reconstructed target files and retained old cache hashes, plus the new inventory-hash cache directory. This does not establish updating an older translation with different target bytes.

Windows validation uses the owner's separate CrossOver `kjh` bottle and the actual extracted archive. Record the archive and executable hashes, PE GUI subsystem, installation receipt, current game code/metadata, loader startup, and installed file hashes. Before every manual-to-automatic handover, capture fresh owner settings and saved-file hashes; an earlier pre-manual baseline is no longer authoritative. Ignore Unity's incrementing settings Revision/session bookkeeping when comparing functional preferences; never overwrite unrelated owner changes merely to restore such counters.

The optional `QA/` plugin is a task-only bridge executing native menu callbacks on Unity's game thread. It is never in the player payload. It requires an exact opt-in file, refuses non-menu buttons, verifies all 32 language entries and ignores a stale request on startup. Wait for the new process's chainloader startup before sending a request; a request written before bridge creation is deliberately ignored. Record unique requests/responses and screenshots at 960×600. CrossOver executable windows could not be bound reliably through native CUA; the scoped native bridge establishes game callback and rendered output evidence without global OS input.

Check the native picker at the top, every scroll region and the last entry. Select all 14 new locales through native callbacks; inspect settings and menu, return/reopen, and verify locale persistence after a normal restart. Also retain an original-language control. Current menu screenshots do not imply full-game linguistic review, save continuation or gameplay progression acceptance.

Font regression: with Dutch selected, open all picker regions and confirm Persian, Hebrew, Hindi and the original Arabic/CJK entries render. Switch Persian → Hindi → Hebrew → Thai → Dutch without recreating the settings view. A correct `TMP_Text.font` name alone is insufficient: a reused caption may still sample the preceding font's atlas. Bind per-label script font and matching shared material before parsing/mesh construction, including a later native `set_font` callback. Preserve the original game layout and compare actual rendered labels. The static-text patch and font fix belong to the shared native adapter; do not alter translation examples to mask a renderer defect.

IL2CPP method regression: destruction callbacks are declared on `TextMeshProUGUI` and `TextMeshPro`, not `TMP_Text` in this exact game. Patch actual metadata declaring types. Verify loader startup after each changed plugin; compilation alone did not detect the old Harmony patch failure.

macOS validation uses a separate game-wrapper runtime snapshot, not another project checkout. Verify original resource/code hashes before installation and keep the owner's original wrapper unchanged. Extract the actual delivery ZIP, verify its ad hoc signature and universal binaries, operate the native launcher UI through CUA, and launch the selected wrapper. This runtime fixture contains the same pinned game as Windows; unavailable Windows-native/Intel-machine execution remains distinct from CrossOver and universal compilation.

Every repeated test must change an input or test a changed hypothesis. Keep prior failing receipts rather than overwriting them. Source recipes and packaged README are pinned in `build.json`; do not edit them during a live build. The current preview overlays all structurally checked authored inputs on the frozen six-scene baseline, including Foreigner/radio changes. Their independent editorial review and full-game runtime acceptance remain pending; the baseline evidence is not promoted to cover changed content.

Changed-content upgrade regression: install the exact published previous payload, verify its first postcondition, then update with different table/catalog/renderer bytes. The new payload pins the previous `all.tsv` to establish old ownership. Reject an unknown same-name owner edit; inject a failure after actual changed promotions and verify old files/receipt; crash and recover in a fresh process before retrying; verify new target hashes, an unchanged repeat, old cache retention and unrelated mods. A successful clean installation or a compression-only upgrade does not replace this check.

Radio runtime regression: execute the shipping renderer in the actual IL2CPP game; verify loader hook setup, localized logical text and weak/intermediate/perfect signal behavior, original-locale fallback, AM/FM multiplier and script handling. Logical .NET tests alone do not verify Harmony/TMP. Keep every probe in the task-only QA assembly, never the player payload.
